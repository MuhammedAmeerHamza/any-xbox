# Contributing

Thank you for helping with this research project.

## Before opening a pull request

1. Open an issue describing the problem or proposed change.
2. Keep changes focused and explain the technical reasoning.
3. Add tests for parsers and deterministic behaviour.
4. Build with CMake and run CTest.
5. Document limitations and known unsupported cases.

## Legal and security boundaries

- Do not submit commercial game files, firmware, private keys, proprietary SDKs, or copyrighted system libraries.
- Do not add DRM, signature, or access-control circumvention.
- Use public documentation, original implementations, and lawfully obtained test data.
- Do not claim compatibility without reproducible evidence.
- Include third-party licence and attribution notices when required.

## Code style

Use C++20, descriptive names, RAII, bounds-checked parsing, and clear error handling. Avoid unnecessary dependencies. The project aims to remain buildable on modest desktop hardware.
